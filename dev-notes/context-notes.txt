### Tarea de esta sesión: **WordPress Multisite Support**

Objetivo: adaptar el plugin para funcionar correctamente en red Multisite sin romper instalaciones de sitio simple.

Cambios principales a implementar:
1. **`class-installer.php`** — `activate()` debe detectar si es Multisite y crear tablas para cada site o solo el actual. Usar `is_multisite()` y `switch_to_blog()` si aplica.
2. **Opciones** — Migrar todas las opciones de plugin de `get_option()` a `get_blog_option( get_current_blog_id(), ... )` donde corresponda, para que cada site tenga su propia configuración.
3. **Network activation** — Hook `wpmu_new_blog` para crear tablas cuando se añade un nuevo site a la red.
4. **`LicenseManager` stub** — Crear `includes/core/class-license-manager.php` con `is_active()` → `true`, `get_plan()` → `'pro'`, `get_site_key()` → `'saas-managed'`.
5. **Network Admin page** — Página en el panel de red para ver todos los sites activos, plan asignado (stub), y activar/desactivar el plugin por site.
6. **Compatibilidad backward** — Todo debe seguir funcionando en instalación de sitio simple (sin Multisite).
7. **Bump versión** → `1.0.25`, `AMIR_DB_VERSION` → `1.2.0` si hay cambios de schema.

Comenzar leyendo `includes/core/class-installer.php` y `amir-booking.php` para entender el estado actual antes de proponer cambios.
