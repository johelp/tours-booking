## Qué es esto

Plugin de WordPress para reservas de tours y experiencias, sin WooCommerce. Nombre de producto: **TourFlow**. Cliente/operador original: Amir Adventours Bacalar (son dos cosas distintas — TourFlow es el software, Amir Adventours el negocio que lo usa; ver README § Tablas de base de datos). Corre en un WordPress Multisite con un subsitio de pruebas en `amiradventours.com/sandbox/`.

Rama de trabajo activa: **`fase1/seguridad-base-codigo2`** (no mergeada a `main` — `main` tiene código viejo v1.0.19 con vulnerabilidades reales, no trabajar ahí).

> **⚠ Prioridad vigente desde 2026-08-18, cierre acordado con el cliente**: pausa de funcionalidad nueva — **no proponer ni construir features salvo que sean un diferenciador enorme**. El foco pasa a ser verificar en producción todo lo que ya se construyó (buscar "sin probar en vivo" en este archivo y en `CONTRIBUTING.md`) y corregir bugs reales en los sitios que ya están en vivo. Motivo: se acumuló deuda de verificación real (13 features marcadas "sin probar en vivo" al cierre de esa sesión) y ya causó un incidente real en producción (`visitsicilyexperiences.com`, § 16.61-16.62 más abajo). Si hace falta código nuevo de todos modos (una integración puntual, una pasarela), usar la arquitectura de plugins satélite (`GUIA-PLUGINS-SATELITE-TOURFLOW.md`) en vez de sumarlo al núcleo. Ver detalle en `feedback_stabilization_priority` (memoria).

## Reglas críticas — leer antes de tocar código

1. **`react-src/` es la fuente del widget de reservas.** Nunca edites `assets/js/booking-widget.js` ni `assets/css/booking-widget.css` directo — son artefactos de build (`cd react-src && npm install && npm run build`). `admin.js` es la excepción: JS plano, se edita directo.
2. **No hay staging con despliegue automático.** El flujo real para probar cambios: armar ZIP del plugin (con `vendor/` generado vía `composer install --no-dev --optimize-autoloader`, no se versiona en git) → subir a `amiradventours.com/sandbox/` vía Plugins → Subir → probar ahí. Los datos viven en tablas `wp_N_amir_*`, reemplazar el plugin no los borra.
3. **Subí `AMIR_VERSION` en `amir-booking.php`** en cualquier cambio a `assets/js/*` o `assets/css/*` — si no, el navegador sirve la versión cacheada vieja.
4. **Cambios de esquema de DB**: agregar a `Installer::create_tables()` (instalaciones nuevas) *y* a `Installer::maybe_update()` con `ALTER TABLE` explícito (instalaciones existentes) — dbDelta solo no alcanza. Subir `AMIR_DB_VERSION`.
5. **Endpoints públicos que devuelven datos de un cliente**: exigir `access_token` (fuerte) o `email` (débil, compatibilidad) vía `BookingManager::authorize_public_access()`. Nunca confiar solo en `booking_ref` — es secuencial y adivinable.
6. **Pasarelas de pago**: todo pasa por `PaymentGatewayInterface` (`includes/payments/`). Para sumar una nueva, implementar la interfaz y registrarla en `PaymentGatewayFactory::make()` — el controlador no se toca.
7. **PHP 8.1 mínimo real** (lo exige `endroid/qr-code`, no es capricho). Todas las queries con `$wpdb->prepare()`. Páginas de admin: nonce + `current_user_can()` sin excepción.
8. No hay PHP instalado en el host directo, pero sí Docker Desktop — usar `docker run --rm -v "$PWD":/app -w /app php:8.1-cli ...` y `composer:2` de la misma forma para lint/tests/build. Correr `vendor/bin/phpunit` (90 tests en `tests/unit/`) antes de armar un ZIP. Si Docker no responde, `open -a Docker` y esperar ~15-30s a que el daemon levante. Node/npm sí están instalados directo en el host (no hace falta Docker para `cd react-src && npm install && npm run build`).
9. **Siempre subir la versión** (`AMIR_VERSION` + el número en el docblock) en cada ZIP que se genera, aunque el cambio sea solo PHP — así el cliente puede versionar qué probó.

## Dudas de producto sin resolver

- ¿Multisite real para varios operadores (plataforma SaaS) o queda como plugin independiente por operador? El `LicenseManager` (stub) deja la puerta abierta sin comprometerse.
- **Retiros semanales con "variantes" de habitación a precio plano y compartido** (consultado 2026-08-25 a partir de un caso real del cliente, [Sicilia Mia](https://caliafarm.com/stag/sicilia-mia/) — antes manejado con variantes de WooCommerce). Ya se puede armar HOY sin código nuevo: cada habitación como un `amir_tour` separado con `price_model='group'` (una sola banda `group_min=1, group_max=<capacidad>`, precio plano sin importar cuántos ocupan el cupo — coincide exacto con "pagás la habitación completa, la repartís si van varios"), fecha gateada a las semanas puntuales publicadas vía Disponibilidad (plantilla "Bloquear todo el año" + reglas "Permitir" por semana, mejorado en v5.8.2), y `require_participant_names` activado (útil para el manifiesto de huéspedes de una habitación compartida). La capacidad total de la propiedad (9 huéspedes / 4 habitaciones en el ejemplo) queda cubierta sola con la suma de capacidades independientes de cada tour, sin necesitar un pool compartido. **Hueco real identificado, sin construir**: el sitio de referencia usa un plan de pago en 3 etapas (depósito al reservar, 50% del resto a -60 días, saldo final a -30 días) — TourFlow hoy soporta depósito (`deposit_enabled`/`deposit_pct`, v5.7.0) + UNA sola cobranza de saldo disparada a mano (botón/link de pago), no dos cobros automáticos programados por fecha. Si el cliente necesita el calendario automático de verdad, es una feature nueva (guardar método de pago + cobro off-session programado) — de lo contrario, el operador puede lograr el mismo resultado mandando el link de saldo a mano en el momento correcto. **Cómo ocultarlas del catálogo y enlazarlas desde la landing**: checkbox "🚫 Ocultar de listados" (`hide_from_lists`) por tour ya existe y saca la habitación de `[flow_tour_list]`/catálogo de Discovery — ojo que NO filtra el archive nativo de WordPress (`archive-amir_tour.php`), así que si el sitio tiene una página "/tours/" pública enlazada, seguirían apareciendo ahí sin filtrar (sin construir un fix para esto todavía, evaluar si aplica). Sumar también "🎯 Reserva directa" (`skip_upsell`) para que la página propia del tour vaya directo al widget clásico sin el upsell de Discovery. **✅ Construido en v5.8.4**: `[flow_booking_variants tour_ids="12,13,14,15"]` — selector de las N variantes con tarjetas (foto/capacidad/precio), embebible directo en la página de Sicilia Mia, sin salir de ahí al reservar.
